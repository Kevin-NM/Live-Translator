# 2026-09-26 YouTube 字幕修正

## 背景與改動

使用者測試舊版後指出四個問題：API Key 無法保存、介面只有單一頁、字幕只在工具頁而未出現在 YouTube、NVIDIA 翻譯每句失敗。截圖的 `integrate.api.nvidia.com/v1/chat/completions` 404 與舊預設模型失效有關；用無效金鑰探測時，該模型回傳 410 並指出於 2026-07-27 停用。NVIDIA `/v1/models` 列有 `google/gemma-4-31b-it`，對該模型用無效金鑰請求回 401，證實路徑與模型名稱有效，但目前仍缺使用者真實金鑰作完整翻譯驗證。

- 新增 `chrome-extension/` Manifest V3 擴充功能。工具列圖示及側邊欄可啟動 YouTube 分頁音訊擷取；service worker 管理 `tabCapture` 與會話，offscreen document 處理 AudioWorklet、WebSocket，content script 將日文和繁中疊到 `.html5-video-player`。擷取音訊會回接播放器輸出，避免啟動擷取後聲音消失。
- 側邊欄提供「字幕」、「留言」、「設定」三個頁籤。翻譯服務、模型、端點、API Key、留言風格明確按「儲存設定」後寫入 `chrome.storage.local`。API Key 保存在 Chrome 本機設定，未寫入專案。
- `app/translation.py` 將 NVIDIA 預設改成 `google/gemma-4-31b-it`，並以單一 user 訊息傳遞指令和原文，配合該模型允許的角色。HTTP 404/410 現會提供可採取行動的模型錯誤；其他失敗顯示狀態碼及有限長度的服務端訊息。
- `app/main.py` 允許 Chrome 擴充功能的 WebSocket Origin 連接本機服務。`web/` 舊版工具頁改成擴充功能安裝指引，移除舊版的瀏覽器擷取腳本，避免使用者繼續開到沒有 YouTube 疊字的介面。
- `README.md` 更新完整安裝、啟動、API 設定及目前範圍。`tests/test_app.py` 增加 NVIDIA payload、模型退役錯誤和擴充功能 WebSocket Origin 測試。

## 驗證與現況

`python -m unittest discover -s tests -v` 六項通過；四個擴充功能 JavaScript 檔案 `node --check` 通過。曾用隔離的 Chrome headless 設定檔嘗試 `--load-extension`；該 Chrome 版本未載入未封裝擴充功能（CDP 中未見本擴充功能），因此尚未驗證真正 YouTube 分頁擷取與影片疊字。依 computer-use 技能的確認政策，透過 Chrome UI 安裝擴充功能需要使用者在動作前明確確認；目前尚未安裝到使用者日常 Chrome。翻譯需要使用者自己的 NVIDIA/OpenAI Key，現僅以 mock 和服務端無效金鑰回應驗證。結束時確認 8788、8765、headless 測試連接埠均沒有監聽程序。

使用者之後已明確允許安裝和測試，但 Browser Use 工具對 `chrome://extensions` 回報 URL 安全政策拒絕，且明文禁止以其他自動化方式繞過。已請使用者手動於 Chrome 載入 `D:\Codex\live translator\chrome-extension`；待其回覆完成後，才能進行實際 Chrome 端到端測試。

## 決策、已知問題與下一步

- 擴充功能不自動送出 YouTube 留言；目前仍是手動貼入與複製。個人回覆風格可保存文字提示，尚無例句學習。
- NVIDIA 模型會隨服務端可用性改變；側邊欄可直接改模型名稱，建議按「測試翻譯」驗證。
- Side panel / tabCapture / offscreen 的整合仍需在實際 Chrome 安裝後測試。取得使用者確認後載入 `chrome-extension/`，在 YouTube 影片上試啟動及停止；若擷取權限或 side panel API 有實際錯誤，修正後重測。
- 若有可用 API Key，從側邊欄測試翻譯，再確認字幕定稿後繁中顯示於影片。
